Architecture

StegoShield is a same-origin Flask application: a server- rendered Jinja frontend calls a JSON REST API (/api/*) on the same server — no separate frontend service, no cross-origin calls. Every uploaded image is validated (extension allow-list, real content sniffing, size and dimension limits) before it reaches either the steganography engine or the steganalysis engine.

  • Steganography engine (app/steganography/) — LSB embedding/extraction and payload framing.
  • Steganalysis engine (app/steganalysis/) — 49-feature extraction, model inference, risk scoring.
  • Image quality & diff analysis (app/services/) — MSE/PSNR/SSIM, channel and histogram comparison.
  • Offline training pipeline (scripts/, ml/) — dataset generation, model training, evaluation; run separately from the web app and its output (ml/models/steganalysis_model.joblib) loaded at request time.

All processing happens locally on the server the app runs on — no uploaded image or extracted message is ever sent to a third-party service.

Steganography

StegoShield uses Least Significant Bit (LSB) embedding. For an 8-bit channel value p and secret bit b:

  • embed: p' = (p & 0xFE) | b — clear the low bit, then set it to b
  • extract: b = p' & 1 — read the low bit back out

Because p' differs from p by at most 1 (of 255), the change is imperceptible. Bits are embedded sequentially across the flattened R, G, B bytes in row-major order; any alpha channel is left untouched.

The secret message is wrapped in a framed payload before embedding — MAGIC (4B) + VERSION (1B) + LENGTH (4B) + SHA-256(message) (32B) + message (N bytes). Decoding checks the magic bytes first (distinguishing "not a StegoShield image" from "corrupted StegoShield image"), then re-hashes the extracted bytes and compares against the stored checksum before trusting them.

Steganalysis

Steganalysis is the defensive counterpart: statistically estimating whether an image likely contains a hidden payload, without needing the original cover for comparison. LSB embedding measurably perturbs a natural image's statistics even though it's visually invisible — it tends to flatten the entropy of the LSB bit-plane toward a uniform 50/50 distribution and weakens the correlation between neighbouring pixels that real photographs normally exhibit.

StegoShield extracts 49 such features per image — channel statistics, entropy, LSB-plane statistics, adjacent-pixel correlation, noise residuals, histogram characteristics, and cross-channel correlation — and feeds them to a trained classifier that outputs a CLEAN / POSSIBLE STEGO verdict, a probability, and a risk level.

ML Pipeline

  • Dataset generation — 9 public-domain photographs (skimage.data) tiled into 256×256 crops, flip/rotate-augmented, then LSB-encoded at 5 payload levels (5/10/20/30/50% capacity utilization).
  • Feature extraction — the same 49-feature extractor used at inference time.
  • Leak-safe split — grouped by source photograph, not by individual crop: no crop, augmentation, or payload-level derivative of one photo ever crosses a train/val/test boundary.
  • Model training — Random Forest, Logistic Regression, and Gradient Boosting trained on the identical split; Random Forest is the deployed primary model.
  • Evaluation — accuracy, precision, recall, F1, balanced accuracy, specificity, false-positive rate, ROC-AUC, PR-AUC, and TPR at a fixed FPR budget, independently reproducible by reloading the saved model.

Why Random Forest, not deep learning? A classical statistical-feature classifier is appropriate for a 960-sample, 9-photo corpus — deep learning on raw pixels needs far more data than this project's small demonstration corpus provides, and would risk memorizing the 9 source photos rather than learning a transferable signal.

Security

Every upload goes through defense-in-depth validation before it reaches any image-processing code:

  • Filename extension allow-list, independent of the declared content type.
  • Real content-type sniffing via libmagic — a renamed non-image file is rejected even if its extension looks correct.
  • File-size limit enforced both at the WSGI layer and again in application code.
  • Pixel-dimension ceiling to prevent decompression-bomb-style memory exhaustion.
  • Rejections return a safe JSON error with no stack traces or internal paths.

Response headers set on every request:

  • Content-Security-Policy: default-src 'self', with a scoped img-src 'self' data: blob: exception for local upload-preview thumbnails — no third-party script, style, or connect exceptions.
  • X-Content-Type-Options: nosniff, X-Frame-Options: DENY, Referrer-Policy: no-referrer.

Fonts, charts, and this application's own JavaScript are all vendored locally rather than loaded from a CDN — the app works fully offline and the CSP needs no third-party host exceptions. On the frontend, values that could originate from user input, uploaded filenames, or API responses are rendered via textContent and DOM APIs rather than innerHTML string interpolation.

Evaluation

Model metrics on this site are read directly from the last training run's saved artifact (ml/models/model_metadata.json) — nothing on the Model or Experiments pages is hand-typed. The primary model (Random Forest, class_weight=None) was selected using 9-fold leave-one-source-photo-out cross-validation, on TPR at a fixed ≤20% false-positive budget — chosen because this application is framed as a human-in-the-loop triage aid, not an autonomous blocker, so the relevant question is how much real signal survives at a false-alarm rate an analyst could tolerate.

That criterion is a stated judgment call, not an objective fact: Gradient Boosting wins on balanced accuracy and specificity in the same cross-validation, and would be the more defensible choice under a symmetric-cost assumption. See Experiments for the full comparison table.

Limitations

This is a portfolio / research-demonstration project, not a production intrusion-detection system:

  • Small, correlated corpus. All samples derive from 9 public-domain photographs, orders of magnitude smaller than research-grade corpora such as BOSSbase (10,000 images) or ALASKA2 (75,000+ images). Crops from the same source photo share content/texture and are not fully independent samples.
  • Clean-image false positives. Even the current model still misclassifies roughly 3 in 10 clean images on the held-out test split — documented on the Model page's confusion matrix, not hidden.
  • Low-payload detection is hard. Small embedded payloads perturb less of the image statistics and are measurably harder to detect than large ones — expected and literature-consistent, but a real limitation of this model.
  • Single embedding algorithm. The classifier is trained only against StegoShield's own sequential LSB embedder; it has not been evaluated against other steganography tools, randomized bit placement, or JPEG-domain (DCT) steganography.
  • Synthetic payloads. Embedded messages are random printable ASCII text, not real-world payload content, which may have different entropy characteristics.

Full discussion, including the diagnostic experiments behind these findings, is in docs/research-notes.md in the repository.
